# S03 — Task dashboard and task completion tracking

## Slice ID and name
S03 — Task dashboard and task completion tracking (plan.md v0.2).

## Requirement IDs covered
FR-02 and AC-FR-02.1–02.2; FR-13 and AC-FR-13.1–13.6; NFR-01, NFR-02, NFR-03; BR-02, BR-06 (PRD v1.2 is a draft; final approval is pending; FR-13 keeps its recorded validation status).

## Goal and scope
A signed-in user sees their own tasks and available deadlines in one place, can mark a task Completed or Incomplete, and can filter by completion status.

## Relevant context only
`app.py`, `Task_Management/__init__.py`, `Domain_Rules/__init__.py`, `Events/__init__.py`, `templates/dashboard.html`, `templates/base.html`, `tests/test_s03_dashboard.py`, `tests/test_cleanup_routes.py`, `README.md`.

## Acceptance criteria and basic checks
- [x] The dashboard shows the user's own tasks with deadline, status and completion date; `/dashboard` requires login.
- [x] Tasks without a deadline remain visible and are marked "Missing deadline information"; they sort after dated tasks.
- [x] Completed and Incomplete tasks are distinguishable (status label plus different action button).
- [x] A task can be marked Completed and reverted to Incomplete (CSRF-protected POST, session user id, 404 for another user's task, domain errors as flash messages).
- [x] Completing does not delete the task or change its deadline.
- [x] The list can be filtered by completion status (`?status=all|incomplete|completed`; unknown values fall back to all).
- [x] Brief guidance for the implemented features is shown.
- [x] The layout works on desktop and mobile (viewport meta tag; single-column page).
- [x] The dashboard has no overdue marking and no priority levels (Priority is S05).
- [x] Manual task entry is disabled by default; with the flag off the form is hidden and `POST /tasks` returns 404.
- [x] No SQL in `app.py`; all queries scoped by `user_id`.
