# S04 — Deadline Management and Conflict Identification

**Status:** Implemented in isolated project copy; awaiting human review and integration.

## Requirements
- FR-03 / AC-FR-03.1–03.2
- FR-04 / AC-FR-04.1

## Approved decisions
- ADR-006 Accepted; Domain Rules owns conflict identification.
- Imported data initiates deadline updates; no manual deadline-edit UI is added.
- Conflict means two or more tasks for the same user have the same exact instant after UTC normalization.
- Input timestamps require ISO 8601 with an explicit UTC offset.
- Existing date-only values remain date-only until replaced; no time is inferred.

## Execution
- Mode: AFK/delegated implementation.
- Reason: approved timestamp validation, normalization, equality detection, and transactional persistence are deterministic.
- Human review is still required before acceptance and integration.

## Implementation
- Added `deadline_at` to task persistence with a forward-compatible migration.
- Added timezone-aware timestamp validation and UTC normalization in Domain Rules.
- Added pure conflict identification in Domain Rules.
- Added Task Management `update_task_deadline` service; publishes `task.deadline_changed` in the same transaction.
- Added `External_Integration.update_imported_task_deadline` as the future S06 integration hook. It does not implement S06 matching or synchronization.
- Dashboard displays timestamp deadlines and flags conflicts.
- Added tests for validation, UTC-equivalent conflicts, per-user isolation, atomic events, and legacy date-only preservation.

## Human review
- Decision: Pending.
- Reason: To be recorded by the assigned reviewer.

## Limitations
- External-source selection, update discovery, and task matching remain S06 scope.
- Priority, schedule, and reminder reactions to the event remain S05/S08/S09 scope.
- `deadline` date compatibility is retained for existing consumers; `deadline_at` is the canonical timestamp for S04.
