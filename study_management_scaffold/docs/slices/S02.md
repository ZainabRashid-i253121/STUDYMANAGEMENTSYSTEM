# S02 — Authentication and authorization

## Slice ID and name
S02 — Registration, authentication, and authorization (plan.md v0.2).

## Requirement IDs covered
NFR-03; ADR-003 (**Proposed**); architecture §5; PRD OQ-51 (referenced by plan.md; the PRD was not available when these records were written).

## Goal and scope
Registration with automatic assignment of the single Registered User role, sign-in, sign-out, protected routes, and per-user record isolation.

## Relevant context only
`Authentication/__init__.py`, `Domain_Rules/__init__.py` (email/password validators), `Data_Access/database.py`, `app.py`, `templates/register.html`, `templates/login.html`, `tests/test_cleanup_routes.py`, `README.md`.

## Acceptance criteria and basic checks
- [x] Registration creates a user and assigns `Registered User`.
- [x] Passwords are stored as salted PBKDF2 hashes, never plaintext.
- [x] Login verifies credentials; logout clears the session when its CSRF token is valid.
- [x] Registration and login POST requests validate CSRF tokens.
- [x] Unauthenticated users cannot reach protected routes (`/dashboard`, task routes).
- [x] Every user-owned service query is scoped by the session `user_id`; another user's record behaves as not found (404).
- [x] Email and password validation goes through Domain Rules (`validate_email`, `validate_password`).
