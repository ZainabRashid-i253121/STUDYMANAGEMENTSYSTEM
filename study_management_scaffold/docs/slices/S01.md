# S01 — Application foundation, persistence, Domain Rules, and module communication

## Slice ID and name
S01 — Application foundation, persistence, Domain Rules, and module communication (plan.md v0.2).

## Requirement IDs covered
ADR-001, ADR-002, ADR-005, ADR-006 (all **Proposed**); architecture §§4–7; NFR-02, NFR-04 (NFR-04 backup/recovery itself belongs to S12 and is not implemented here).

## Goal and scope
A runnable foundation following the Layered Modular Monolith structure: Presentation (`app.py`, templates), Business (module services and `Domain_Rules`), Data Access (`Data_Access`); centralized SQLite persistence; transaction support; a shared Domain Rules gateway; service interfaces; and an event publication/consumption foundation.

## Relevant context only
`Data_Access/database.py`, `Data_Access/event_store.py`, `Events/__init__.py`, `Domain_Rules/__init__.py`, `Task_Management/__init__.py`, `Authentication/__init__.py`, `Priority/`, `Schedule/`, `Reminder/`, `External_Integration/`, `templates/base.html`, `tests/test_database.py`, `tests/test_domain_rules.py`, `tests/test_module_interfaces.py`, `tests/test_events.py`, `README.md`.

## Dependencies and decision gates
| Gate | Status |
|---|---|
| G-01 (language, framework, database, event mechanism, test framework) | **PROVISIONAL** — Flask, SQLite, pytest and the database-backed event mechanism were chosen by the AI, not approved by the group. `AGENTS.md` says the project documents do not establish an event mechanism; human approval is required. |
| G-12 (backup frequency, event retry interval, maximum attempts) | **PROVISIONAL** for retry constants (`EVENT_RETRY_INTERVAL_SECONDS`, `EVENT_MAX_ATTEMPTS`); backup is **not implemented** (S12). |
| G-15 (user-visible behavior when an event is delayed/fails) | **OPEN** — no user-visible behavior defined or implemented. |
| OI-08 (who may inspect failed events) | **OPEN** — events are stored; no operator process or Administrator role exists. |

## Acceptance criteria and basic checks
- [x] The application starts; layers have the documented responsibilities (`app.py` has no SQL).
- [x] Persistent data is accessed only through `Data_Access` (event SQL is in `Data_Access/event_store.py`).
- [x] A state-changing operation can be rejected by Domain Rules without committing its changes (task and event roll back together).
- [x] Modules communicate through public service interfaces and events rather than private access.
- [x] Event processing records identifiers, prevents duplicate handling, retries, and logs failures (PROVISIONAL policy).
- [x] The UI shell supports desktop and mobile layouts (viewport meta tag; responsive single-column page).
- [x] Domain Rules is the single validation gateway: task, schedule, reminder, import and (since the gap-fix round) email/password validation.
- [x] `init_db()` creates all tables and migrates legacy databases (nullable deadline, new statuses) without data loss.
